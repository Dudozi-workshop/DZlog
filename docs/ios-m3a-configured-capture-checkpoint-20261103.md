테스트 코드만 변경한 `186dbfa2`의 [iOS 코어 41641905025](https://github.com/Dudozi-workshop/DZlog/actions/runs/41641905025)·[Android 41641905090](https://github.com/Dudozi-workshop/DZlog/actions/runs/41641905090) 확인도 통과했다. 두 실행은 관련 입력이 동일한 이전 성공 결과를 재사용했으며 새 코어/Android 테스트 실행으로 세지 않는다.

첫 전체 UI 실행(41636131802)은 14개 통과, 신규 2개의 종료 후 스크린샷 오류, 20분 실행 제한으로 끝났다. 신규 두 테스트는 저장·복구·갤러리 단계의 확인을 마친 뒤 정리 단계에서 실패했다. 마지막 갤러리 프로세스를 유지하고 종료된 앱의 스크린샷 요청을 방지하도록 수정했다. 전체 UI 한도는 30분으로 조정했으며 재검증은 동일한 네이티브 프레임워크 캐시를 사용했다. 재실행은 18개 전부 통과했고, XCTest 실행 시간은 1,016초였다. 전체 UI 단계의 성공과 각 테스트 통과 로그를 확인했다.

추가한 XCTest는 실제 촬영 설정 화면을 조작하여 문서를 저장하고, 실제 운영 저장 진입점·Skia 합성·PhotoKit 저장·재실행·갤러리 조회를 실행한다. **센서 입력 JPEG만 합성 데이터**다. 실제 iPhone 카메라를 검증한 것으로 취급하지 않는다.

추가 검증 범위:

- 원본만 1개, 결과만 1개, 원본과 결과 2개가 정확한 역할로 생성되는지 확인.
- 저장된 사진을 PhotoKit에서 다시 읽고 이미지 크기 및 결과 생성 여부 확인.
- 정상 저장 후 다음 번호 12 → 13과 설정이 재실행 후 유지되는지 확인.
- 세 모드 모두 실제 PhotoKit 저장 후 워크스페이스 기록 실패를 주입하고, 재실행으로 한 번만 번호가 증가하는지 확인.
- 확정 롤백은 번호를 바꾸지 않고 재시도할 수 있는지 네이티브 단위 테스트로 확인.
- 다른 촬영 ID 또는 변경된 문서로는 복구 기록을 폐기할 수 없는지 확인.

## 남은 구현 범위와 제한

1. **병합 셀의 결과만/동시 저장은 지원하지 않는다.** 촬영 진입에서 안내하고 차단한다. 해당 문서는 원본만 저장할 수 있다. 지원되지 않는 결과를 조용히 저장하지 않는다.
2. 표의 위치·크기는 저장 결과에 연결되었지만, 실제 센서 화면 위 실시간 표 조작·드래그·리사이즈와 Android 수준의 카메라 UI는 완료되지 않았다.
3. 한글·폰트·스타일의 Android/iOS 픽셀 비교, 실제 JPEG 방향·회전·크롭 검증은 남아 있다.
4. 초점·줌·플래시·저장 취소와 폴더/사진 관리까지 포함한 Android 전체 갤러리 UX 동등성은 별도 후속 범위다. 현재 갤러리는 읽기 중심이다.
5. 사진 존재 여부가 불명확하거나 문서가 충돌한 복구 기록은 사용자 데이터를 지키기 위해 자동 해제하지 않는다. 실제 장애 사례 확인 후 처리해야 한다.
6. ARM64 unsigned 컴파일 성공은 설치 가능한 서명 IPA 또는 TestFlight 배포 완료가 아니다. 서명·설치 경로 준비가 필요하다.
