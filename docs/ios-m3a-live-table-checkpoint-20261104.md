# iOS M3-A 실시간 표 배치 구현 — 네이티브 검증 대기

PR #87의 기존 검증 완료 코드 `a3be0db` 이후 남은 카메라 표 조작을 구현했다. PR은 Draft·미병합으로 유지한다.

## 이번 변경

- 네이티브 카메라 레이어 위에 실제 표 PNG를 표시한다. 현재 저장 문서의 스타일·병합·동적 셀·번호와 같은 렌더러를 사용하며, 날짜·시간은 초 단위로 갱신한다.
- 표 영역 드래그로 이동하고 우측 아래 핸들로 비율을 유지하며 크기를 조절한다. 제스처 종료 시 기존 iOS `capturePlacement`에 저장하고 이후 결과 사진에 같은 배치를 적용한다. 취소 시 원래 배치로 복귀한다.
- CUSTOM 90도 회전의 화면 경계와 실제 래스터 원점을 같은 계산으로 묶었다. 사진 경계와 10~100% 크기 범위를 지킨다.
- 제스처 중에는 PNG를 계속 인코딩하지 않고 네이티브 이미지 변환을 사용한다. 종료 시 다시 렌더링하고, 반복 렌더링의 Skia 자원을 명시적으로 해제한다.
- 카메라는 전체 사진 영역을 fit으로 표시하며 네이티브 좌표 변환으로 표시 영역을 구한다. 실제 사진과 미리보기 비율이 맞지 않으면 결과 저장을 차단한다. 원본 모드는 기존 원본 저장 경로를 사용한다.
- 저장 중·복구 대기에는 표 조작을 잠그고, 조작 중에는 촬영·화면 이동을 막는다. 시계 갱신이 진행 중인 드래그를 초기화하지 않도록 했다.
- Android·common 프로덕션 소스 및 Android 데이터는 변경하지 않았다.

## 추가한 검증

실제 UIKit 제스처와 iOS 워크스페이스를 사용하는 독립 fixture를 추가했다. fixture의 센서 입력만 160×240 합성 JPEG이며 실제 카메라 성공을 가장하지 않는다.

1. 표 이동·축소 → 저장 배치 값 변경 → 실제 PhotoKit 저장 → 번호 12→13 → 재실행 후 배치·크기·번호 유지.
2. 모든 앵커·가로/세로 이미지·90도 회전·큰 양/음 드래그·최소/최대 크기·NaN 거부.
3. 비율이 다른 JPEG를 실제 저장 진입점에 넣어 거부하고, 번호·PhotoKit 인덱스·대기 기록이 바뀌지 않는지 검사.
4. 90도 표의 native 핸들 방향, 조작 잠금/해제와 배치 유지.

기존 17개 media 테스트에 새 2개를 더해 관련 19개를 우선 실행하도록 연결했다. 전체 UI는 27개가 된다. 새 코드의 Apple SDK 컴파일·네이티브 UI 결과는 아직 미확정이며, 이전 코어 86개/전체 UI 25개 성공을 이번 변경의 통과로 계산하지 않는다.

로컬 `git diff --check`, `bash -n scripts/ios/test-ui-poc.sh` 통과. 현재 환경에는 Kotlin/Swift Apple SDK가 없어 네이티브 검증은 macOS CI에서 수행한다. CI를 요청한 뒤 실시간 대기는 하지 않는다.

## 2026-11-05 컴파일 참조 수정

- `3e0f200`의 코어·Android CI는 성공했다. iPhone/시뮬레이터는 동일한 네이티브 참조 오류로 컴파일 실패했고, 관련 UI 19개는 실행되지 않았다.
- 오류 근거: iPhone 실행 `41800911508`/job `126476138196`, UI 실행 `41800911668`/job `126476138874`.
- UIKit의 정수형 상수는 클래스 멤버 대신 최상위 상수로 참조한다. 읽기 전용으로 노출된 프레임 프로퍼티는 명시적인 `setFrame`으로 갱신한다.
- AVFoundation 좌표 변환에는 실제 Objective-C selector인 `rectForMetadataOutputRectOfInterest`를 사용한다. Swift의 메서드 표기와 혼용하지 않는다.
- 핸들은 노출이 확인된 고유 접근성 label로 선택한다. 실제 핸들 이동·크기·값·영속화·PhotoKit 검증은 유지하며 테스트를 생략하거나 센서 권한을 가장하지 않는다.
- 로컬 공백 검사와 shell 문법 검사 후 네이티브 CI를 재요청한다. 새 iPhone 빌드·UI 결과는 아직 미확정이며, CI 대기는 하지 않는다.

## 2026-11-06 관련 UI 결과 및 통합 검증 요청

- `0c800b2`는 공유 코어와 iPhone ARM64·unsigned 호스트 빌드를 통과했다. UIKit 참조 수정 이후 실제 네이티브 UI 19개가 실행됐고 18개 통과, 1개 실패했다.
- UI 근거: 실행 `42041150372`/job `127291980302`, 19개 실행·실패 1개. 90도·잠금·경계·비율 불일치 저장 차단 및 기존 PhotoKit/갤러리 17개는 통과했다.
- 실패는 재실행 후 위치 비율을 크기 조절 전 값과 비교한 테스트 기대값 오류였다. 위치 비율은 사진 전체가 아닌 표를 제외한 여유 공간 기준이므로, 크기가 바뀌면 화면의 좌상단을 유지하면서 비율을 다시 계산하는 것이 맞다. 예: 이동 직후 가로 59/세로 29 → 축소 후 가로 47/세로 28.
- 테스트는 축소 후 최종 비율·크기를 기록해 저장/재실행 값과 정확히 비교하도록 수정했다. 축소 시 너비·높이가 실제로 줄고 좌상단 위치가 정수 퍼센트 반올림 범위 안에서 유지되는지도 추가 확인한다. 제품 배치 계산은 변경하지 않는다.
- Android 실행 `42041150247`/job `127291979660`은 Robolectric artifact 다운로드의 Maven HTTP 429로 테스트 전에 중단됐다. Android 제품 코드 변경 없이 새 CI에서 재시도한다.
- 수정은 테스트·보고서에 한정하며 전체 UI 27개 통합 검증을 요청한다. 새 결과는 미확정이며 대기/실시간 모니터링하지 않는다. PR #87은 Draft·미병합으로 유지한다.

## 2026-11-06 iOS CI 실행 환경 교체

- `fe61def`에서 전체 UI·iPhone·코어 작업이 runner 배정 전 취소됐다. 단계/실행 로그가 없어 제품 코드 실패로 계산하지 않는다. 취소된 실행: UI `42223326595`, 기기 `42223326599`, 코어 `42223326601`.
- 세 작업 모두 `macos-14`를 사용하고 있었다. GitHub 공식 공지상 이 이미지의 지원은 2026-11-02 종료됐다. 지원 중인 arm64 `macos-15`로 변경하고 제공되는 Xcode 16.4를 명시적으로 선택한다.
- UI/코어의 해당 workflow 파일도 검증 입력 fingerprint에 포함되므로 이전 실행 결과를 그대로 재사용하지 않는다. UI 프레임워크 캐시는 실제 Xcode/Java 버전을 포함한 키로 구분된다. Android 워크플로우·앱·데이터는 변경하지 않는다.
- 로컬 YAML 3개 파싱·runner/Xcode 선택 검사와 캐시 fingerprint 확인을 통과했다. 코어/UI/프레임워크 입력은 변경되고 Android 입력은 유지된다.
- 새 커밋에도 `[ios-full-ui]`를 유지해 전체 27개 통합 검증을 요청한다. 새 runner에서의 결과는 아직 미확정이며 대기하지 않는다.
