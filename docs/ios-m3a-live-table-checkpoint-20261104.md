# iOS M3-A 실시간 표 배치 구현 — 네이티브 검증 대기

PR #87의 기존 검증 완료 코드 `a3be0db` 이후 남은 카메라 표 조작을 구현했다. PR은 Draft·미병합으로 유지한다.

## 이번 변경

- 네이티브 카메라 레이어 위에 실제 표 PNG를 표시한다. 현재 저장 문서의 스타일·병합·동적 셀·번호와 같은 렌더러를 사용하며, 날짜·시간은 초 단위로 갱신한다.
- 표 영역 드래그로 이동하고 우측 아래 핸들로 비율을 유지하며 크기를 조절한다. 제스처 종료 시 기존 iOS `capturePlacement`에 저장하고 이후 결과 사진에 같은 배치를 적용한다. 취소 시 원래 배치로 복귀한다.
- CUSTOM 90도 회전의 화면 경계와 실제 래스터 원점을 같은 계산으로 묶었다. 사진 경계와 10~100% 크기 범위를 지킨다.
- 제스처 중에는 PNG를 계속 인코딩하지 않고 네이티브 이미지 변환을 사용한다. 종료 시 다시 렌더링하고, 반복 렌더링의 Skia 자원을 명시적으로 해제한다.
- 카메라는 전체 사진 영역을 fit으로 표시하며 네이티브 좌표 변환으로 표시 영역을 구한다. 실제 사진과 미리보기 비율이 맞지 않으면 결과 저장을 차단한다. 원본 모드는 기존 원본 저장 경로를 사용한다.
- 저장 중·복구 대기에는 표 조작을 잠그고, 조작 중에는 촬영·화면 이동을 막는다. 시계 갱신이 진행 중인 드래그를 초기화하지 않도록 했다.
- Android·common 프로덕션 소스 및 Android 데이터는 변경하지 않았다.

## 추가한 검증

실제 UIKit 제스처와 iOS 워크스페이스를 사용하는 독립 fixture를 추가했다. fixture의 센서 입력만 160×240 합성 JPEG이며 실제 카메라 성공을 가장하지 않는다.

1. 표 이동·축소 → 저장 배치 값 변경 → 실제 PhotoKit 저장 → 번호 12→13 → 재실행 후 배치·크기·번호 유지.
2. 모든 앵커·가로/세로 이미지·90도 회전·큰 양/음 드래그·최소/최대 크기·NaN 거부.
3. 비율이 다른 JPEG를 실제 저장 진입점에 넣어 거부하고, 번호·PhotoKit 인덱스·대기 기록이 바뀌지 않는지 검사.
4. 90도 표의 native 핸들 방향, 조작 잠금/해제와 배치 유지.

기존 17개 media 테스트에 새 2개를 더해 관련 19개를 우선 실행하도록 연결했다. 전체 UI는 27개가 된다. 새 코드의 Apple SDK 컴파일·네이티브 UI 결과는 아직 미확정이며, 이전 코어 86개/전체 UI 25개 성공을 이번 변경의 통과로 계산하지 않는다.

로컬 `git diff --check`, `bash -n scripts/ios/test-ui-poc.sh` 통과. 현재 환경에는 Kotlin/Swift Apple SDK가 없어 네이티브 검증은 macOS CI에서 수행한다. CI를 요청한 뒤 실시간 대기는 하지 않는다.
