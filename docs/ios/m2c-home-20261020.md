# M2-C2 기존 홈 UI 재사용

기준 #76 02e186d5. 새 PR 없이 같은 브랜치에 이어서 구현한다.

- HomeScreen 표시 본문을 HomeContent로 이동한다. Android lifecycle/ViewModel/MediaStore·Coil,
  기존 다음 번호 계산·문자열 리소스·내비게이션 콜백·저장 정보 창과 refresh 순서는 유지한다.
- HomeRecentCaptureContent는 기존 사진/빈 상태 배치를 재사용하고 이미지 로딩만 슬롯으로 받는다.
  AlbumViewAction/IconButton·3구역 layout·그림자 mask를 이동하며 HomeUiSpec 값은 유지한다.
- HomeAmbientContent는 기존 배경·잎 그림자의 위치·크기·mask·애니메이션을 재사용한다.
  Android는 기존 R.drawable을 계속 로드하고 iOS는 같은 PNG blob을 번들에서 로드한다.
  새 디자인/이미지 생성은 없다. Xcode와 수동 Swift build 모두 기존 PNG를 포함한다.
- iOS 메모리 전용 host에서 기존 홈→목록→미리보기→선택→홈/다시 목록→뒤로가기를 연결한다.
  실제 사진 조회·카메라·편집·저장/설정/앨범은 아직 연결하지 않아 해당 버튼을 비활성화한다.
  Android의 활성 기본값/콜백은 그대로다. iOS 수치는 합성 표시이며 실제 촬영 계산 검증이 아니다.
- 기존 목록 검사1개를 홈 경유로 확장하고 기존 미리보기/가로·세로3개를 유지한다.
  첫 홈/빈 최근 사진 상태와 목록 screenshot을 xcresult에 남긴다.

검증 근거/최종 HEAD는 PR #76에 기록한다. 실기기·정식 디자인 승인·AX/VoiceOver·140%·다기기,
사진·영속 저장·촬영/편집/설정/앨범 전체 이동은 미검증이다. Android 기준 d6e53c9a와
기존 PR #37/#62/#65 및 출시용 integration을 변경/병합하지 않는다.
Notion 상세 기록의 이전 크레딧 차단 이후 현재 진행 기록을 다시 반영했다. 최신 상태는 PR과 기존 Notion 기획 문서를 확인한다.

## 자동 검증 마감

구현/조작 검증 기준 f065de5e23612427d2db187f6cf138dd09c6d0e5.

- Android 변경f8d86c1c: CI39381098448 JUnit XML Android607/shared JVM61개,
  실패·오류·건너뜀0. 이후 UI 검사/번들 설정만 수정한 실행은 동일 입력 성공 근거 재사용.
- iOS core58개 근거39355103841은 공통 입력 불변으로 재사용한다.
- iPhone 공통 코드 compile·simulator framework build는 f8d86c1c에서 통과했다.
  이후 Kotlin UI가 바뀌지 않아 동일 framework exact cache를 재사용했다.
- UI39384946538 실제4개 PASS/실패0, artifact12246794187. 홈 기본/변경된 이름·번호를
  실제 screenshot OCR로 확인하고 목록/미리보기/선택/복귀/뒤로가기·가로·세로 조작 수행.
  원본과 번들 PNG cmp 통과, SHA256 57741fe0c9faabab9d9e74c6199d585f05631ad98fec56bd6abe0fbae699d589.
- Xcode PNG 가공으로 Skia Image::makeFromEncoded 종료가 발생했다. 압축 OFF만으로는
  남아 있던 가공 단계를 제거하지 못해 PBXCopyFilesBuildPhase 원본 복사로 수정했다.
  앱 실행 전에 bundle bytes를 확인한다. 최종은 build-for-testing1회 + byte 검증 +
  test-without-building이며 중복 app compile/별도 smoke launch는 하지 않는다.
- 홈 버튼 AX label은 아이콘 설명만 노출되어 이름·번호를 실제 화면 OCR로 검사한다.
  AX/VoiceOver가 해결됐다는 의미는 아니다. 앞선 실패와 취소를 PASS로 소급하지 않는다.
- 홈 검사1개244.569초/전체4개319.107초는 검사 소요 시간이며 앱 촬영/저장 성능값이 아니다.
  애니메이션 화면의 snapshot/AX/OCR 대기 비용은 후속 CI 최적화 후보로 남긴다.

실기기·정식 디자인 승인과 나머지 화면/영속 저장·카메라 연결은 후속이다.

## M2-C4 표 스타일 패널 최초 재사용 · 검증 대기

기준 a5ec36df. 사용자 요청에 따라 구현/정적 확인 후 CI를 시작하고 완료 대기 없이 보고한다.

- 기존 TableEditorStylePanel을 sharedUi로 이동했다. public visibility 한 곳 외 원문 동일을
  비교 확인했다. Android 호출/세션/저장 콜백·데이터와 패널 디자인은 변경하지 않는다.
- 배경/투명도/글자 크기/정렬/테두리의 기존 UI와 onDraftChange를 공유한다.
- iOS --table-style 전용 확인 화면에서 메모리 draft 변경과 뒤로가기/재열기를 연결했다.
  진단용 상태 문구는 PoC host의 패널 바깥에 두며 기존 패널에는 추가하지 않았다.
  기본 iOS 홈의 표 편집 버튼은 전체 편집 연결 전까지 비활성 상태를 유지한다.
- 새 실제 조작 검사1개: 어둡게/오른쪽 선택→draft 관측→뒤로가기/재열기 유지→투명 선택 시
  기존 투명도 행 숨김. 나머지5개 검사는 유지한다.
- 정적 확인 PASS: 원문 비교, diff --check. Android/iOS 빌드와 조작 검사는 CI 대기이며
  성공으로 표시하지 않는다. 실제 표 렌더링에 스타일 반영/슬라이더·테두리 조작/영구 저장/
  전체 편집 화면/실기기 검수는 이번 완료 범위가 아니다.
- 같은 Draft PR #76에서 계속하며 병합/배포하지 않는다. 다음 사용자 진행 지시 시 CI 최종
  상태를 먼저 확인하고 실패가 있으면 최소 수정한다.
