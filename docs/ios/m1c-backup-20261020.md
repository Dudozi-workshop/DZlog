# M1-C · portable template backup

기준: B5 `fae7bfb70406c8b9f5a5513485bea32143b25e8b`.

- 기존 template/catalog JSON 변환, archive codec/validation/merge를 shared로 이동한다.
  모델/package/필드/기본값, schema1/payload 원문 checksum, export seed=1,
  기존 목록·활성 선택 보호 정책은 유지한다.
- JSON DOM 경계만 expect/actual로 분리한다. JVM은 org.json을 그대로 호출한다.
  Maven org.json은 jvmMain compileOnly 및 jvmTest 전용이다. Android 런타임은
  기존 시스템 org.json을 사용한다.
- iOS는 kotlinx.serialization-json 1.7.3의 DOM을 사용한다. 의존은 iosMain에만
  추가하고 앱 전체 Kotlin 2.0.21/Compose/AGP 버전은 변경하지 않는다.
  https://github.com/Kotlin/kotlinx.serialization/releases/tag/v1.7.3
- native 어댑터는 JSON 숫자 lexical form으로 Int/Long/Double을 구분한다.
  mutable DOM으로 nested put을 반영한다. JVM은 기존 동작을 직접 위임한다.
- JVM MessageDigest/UUID/System clock 및 iOS CommonCrypto/NSUUID/NSDate만
  플랫폼 구현에 둔다. 빈 문자열·ASCII·한글/emoji SHA-256 고정 벡터를 검사한다.
- 기존 backup 테스트7개를 commonTest로 이동하고, 고정 B5 합성 schema1 입력의
  지원 모델 전체 round-trip, 엄격 정수/손상 거절, SHA 검사를3개 추가한다.
  B5 Android backup→capture 및 기존 repository safety 검사는 그대로 유지한다.
- Android validator 테스트용 org.json 진입점은 얇은 문자열 bridge로 남긴다.
  실제 archive 검증 정책은 shared 한 곳에서만 수행한다.

한계:

- native JSON 입력은 표준 JSON을 대상으로 한다. org.json의 비표준 JSON 문법
  (주석/따옴표 없는 key 등)까지 native에서 허용한다고 주장하지 않는다.
  Android는 기존 parser를 쓰므로 기존 허용 동작을 유지한다.
- 모델 round-trip은 기존 정규화/seed 정책을 반영한다. 알 수 없는 미래 필드나
  JSON key 순서/공백까지 무손실이라고 주장하지 않는다.
- 기존 SAF/DataStore/사진/설정/실제 저장은 이동하지 않는다. iOS Files import/export,
  실제 사용자 백업, 기기 검수는 후속이다.
- 촬영 계획 orchestration 이관은 이 백업 패치 검증 후 별도 작은 패치로 진행한다.
