# Table Editor V2 UX Decisions

기준 브랜치: `feat/table-editor-v2-ux-mock`

이 문서는 표 상세설정 V2의 UI/UX 확정사항을 고정한다.
저장 규칙의 내부 정책/카운터 스코프 계산은 별도 논의 범위이며, 여기서는 진입점과 UI 책임 경계만 정의한다.

## 1. 전체 편집 원칙

- 표에서는 직접 셀을 선택하고 수정한다.
- 셀 = 내용/데이터 타입
- 레이아웃 = 표 내부 구조
- 스타일 = 표가 보이는 방식
- 저장 규칙 = 저장 방식
- 실제 표 전체 배치/크기 = 카메라 Preview
- 별도의 `내용` 탭은 두지 않는다.
- 내부 구현 용어인 `slot`, `G1/G2` 등은 사용자 UI에 노출하지 않는다.
- 기본 화면은 설명보다 실제 표를 중심으로 구성한다.
- 편집 중 변경은 화면에 즉시 반영하되 영구 저장은 상단 `저장`으로 확정한다.

## 2. 메인 편집 화면

상단:
- 뒤로
- 제목: `표 편집`
- 현재 템플릿명
- Undo
- Redo
- 저장

중앙:
- 실제 표 미리보기를 화면의 주영역으로 사용
- 안내 문구는 `수정할 셀을 눌러보세요` 수준의 짧은 힌트만 허용
- 별도의 설명 카드/온보딩 카드는 기본 상태에서 노출하지 않음

하단 고정 액션 3개:
1. 레이아웃
2. 스타일
3. 저장 규칙

세 버튼은 동일 계층으로 표현한다.

## 3. 셀 선택/편집

### 3.1 기본 동작

- 셀 탭 시 필요한 높이만 사용하는 하단 편집 패널을 연다.
- 패널을 화면 절반 이상 덮는 고정형으로 만들지 않는다.
- 패널은 `×` 또는 바깥 탭으로 닫을 수 있다.
- 다른 셀을 탭하면 현재 셀 편집을 종료하고 새 셀로 즉시 전환한다.
- 별도의 셀별 저장 버튼은 두지 않는다.
- 빈 셀은 편집 화면에서 옅은 `빈 셀` 플레이스홀더를 표시하고 실제 촬영/출력에서는 숨긴다.
- 빈 셀의 기본 타입은 텍스트다.

### 3.2 셀 타입 선택

기본 패널에서는 현재 타입을 한 줄로 표시한다.

예:
```
선택한 셀                         ×

[ Draper                           ]

셀 종류                 텍스트  >
```

`셀 종류`를 누르면 Bottom Sheet에서 6개 타입을 2열 그리드로 한 번에 보여준다.

타입:
- 텍스트
- 숫자
- 자동번호 (내부 COUNTER)
- 날짜
- 시간
- 순환문구

일반 타입 전환에는 확인창을 두지 않는다.
기존 값 손실 가능성이 명확한 경우에만 경고한다.

타입 변경 시 기존 값은 가능한 범위에서 유지하고,
호환되지 않으면 새 타입의 기본값으로 전환한다.

### 3.3 타입별 기본 UI

- 텍스트: 값 입력
- 숫자: 값 입력
- 자동번호: 현재/다음 번호 + 최소 동기화 정보
- 날짜: 현재 날짜 미리보기 + 날짜 형식
- 시간: 현재 시간 미리보기 + 시간 형식
- 순환문구: 현재 문구 + 문구 세트

키보드:
- 텍스트/숫자 셀 선택 시 입력칸 자동 포커스 + 키보드 자동 호출
- 숫자는 숫자 전용 키패드 사용
- 자동번호/날짜/시간/순환문구는 키보드 자동 호출 안 함
- 텍스트/숫자 입력 후 Enter는 현재 셀 입력을 유지하고 키보드만 닫음
- 다음 셀로 자동 이동하지 않음

날짜/시간:
- 새 셀에서는 현재 날짜/시간을 기본 표시
- 자주 쓰는 형식만 프리셋으로 제공
- 직접 포맷 문자열 입력은 MVP에서 제외
- 현재 선택 형식에 체크 표시
- 형식 선택 즉시 반영 후 Sheet 자동 닫기

자동번호:
- 현재 번호 직접 수정 가능
- 저장 전 변경은 Undo 가능
- 동기화 관련 액션은 최소 정보만 노출

순환문구:
- 기본 셀 화면에는 `문구 세트 >` 중심으로 노출
- 문구 추가/삭제/순서 변경/전환 간격은 문구 세트 상세에서 처리
- 문구 세트 미지정 시 `문구 세트 선택` 표시
- 촬영 화면에서는 미지정 값을 빈 값으로 처리

기본 셀 편집에서 제외:
- 정렬
- 글자 크기
- 글자색
- 배경
- 파일명
- 저장경로
- 카운터 스코프

셀 편집의 책임은 `내용/타입`에 한정한다.

## 4. 선택 상태

단일 셀:
- 외곽선 강조

레이아웃 범위:
- 연한 브랜드 컬러 반투명 채움
- 선택 범위 전체를 감싸는 외곽선
- 내부 그리드선은 유지
- 드래그 중 외곽선은 실시간 업데이트

권장 시각 기본값:
- 내부 채움: 브랜드 컬러 약 10~15% opacity
- 전체 외곽선: 약 2dp

## 5. 레이아웃

### 5.1 범위

레이아웃은 표 내부 구조만 편집한다.
표 전체의 화면상 위치/전체 크기는 여기서 다루지 않는다.

레이아웃 모드 진입 시:
- 셀 편집 패널 닫기
- 키보드 닫기
- 구조 편집 전용 상태로 전환

레이아웃 모드에서 시스템 뒤로가기/뒤로가기 제스처:
- 앱 종료 금지
- 레이아웃 모드만 종료
- 메인 표 편집 화면으로 복귀
- 상단 `완료`와 같은 결과

### 5.2 하단 액션

하단 고정 액션은 정확히 4개:
- `+ 행`
- `+ 열`
- `병합` 또는 `병합 해제`
- `삭제`

상태:
- 무선택: `+ 행`, `+ 열`만 활성
- 단일 셀: 병합 비활성
- 직사각형 다중 범위: 병합 활성
- 병합 셀 선택: `병합 해제`로 전환

### 5.3 범위 선택

확정 방식:
- 탭 = 단일 셀 선택
- 표 내부 드래그 = 직사각형 범위 선택

규칙:
- 레이아웃 모드에서만 활성
- 시작점과 이동은 표 내부로 제한
- 짧은 탭과 드래그를 구분하기 위해 약 8~12dp 이동 임계값 사용
- 롱프레스 지연은 사용하지 않음
- 드래그 중 직사각형 범위를 실시간 갱신
- 손가락이 표 밖으로 나가면 마지막 유효 셀 기준으로 clamp/freeze
- 비직사각형 선택은 허용하지 않음
- 두 번째 셀 탭으로 범위를 만드는 방식은 사용하지 않음

### 5.4 행/열 추가

- 단일 셀 선택: 해당 행 바로 아래에 행 추가
- 단일 셀 선택: 해당 열 바로 오른쪽에 열 추가
- 범위 선택: 범위 마지막 행 아래 / 가장 오른쪽 열 다음에 추가
- 무선택: 맨 아래 / 맨 오른쪽에 추가
- 병합 영역 내부에는 삽입하지 않고 병합 블록 바깥 경계를 기준으로 추가
- 추가 후 선택 상태 해제

### 5.5 삭제

`삭제` 탭 시 작은 Bottom Sheet:
```
삭제

[ 행 삭제 ]
[ 열 삭제 ]

취소
```

동작:
- 단일 셀: 해당 행 또는 열 삭제
- 범위: 범위와 교차하는 모든 행 또는 모든 열 삭제
- 셀 내용 삭제는 레이아웃 삭제에 포함하지 않음
- 삭제 후 선택 상태 해제
- 병합 구조는 안전하게 정규화
- 불필요한 경고창은 사용하지 않음

### 5.6 병합/병합 해제

병합:
- 2개 이상 셀의 직사각형 범위에서만 허용
- 기존 병합 셀을 일부만 포함하면 병합 불가
- 기존 병합 영역 전체를 포함하면 새 병합 범위에 포함 가능
- 병합 후 내부 경계 제거
- 선택 외곽선은 병합 결과 전체를 감쌈

값 처리:
- 복수 셀에 값이 있을 경우 왼쪽 위 셀 값만 유지

경고 문구:
```
셀을 병합할까요?

병합하면 왼쪽 위 셀의 값만 유지됩니다.

[취소]   [병합]
```

`선택한 셀에 여러 값이 있습니다.` 문구는 사용하지 않는다.

하나의 값만 존재하면 별도 경고 없이 병합 가능.

병합 해제:
- 병합 셀 선택 시 버튼을 `병합 해제`로 전환
- 해제 후 일반 그리드로 복원

### 5.7 행 높이/열 너비

- 세로 경계 드래그 = 열 너비
- 가로 경계 드래그 = 행 높이
- 별도 슬라이더는 사용하지 않음
- 선 자체는 얇게 유지하되 터치 hit area는 약 20dp 확보
- 드래그 중 활성 경계 강조
- 크기 변경은 실시간 반영
- 숫자 tooltip은 선택적 보조 피드백
- 한 행/열을 늘려도 인접 행/열을 자동 축소하지 않음
- 표가 커지면 편집 영역에서 스크롤/스케일로 대응

최소값 기본:
- 행 높이 약 44dp
- 열 너비 약 72dp
- 최소값 이하로 축소 불가
- 최소 도달 시 경고창 없이 미세 highlight/haptic 정도만 허용
- 긴 텍스트는 한 줄 + ellipsis
- 레이아웃 모드에서는 자동 줄바꿈하지 않음

## 6. 스타일

스타일 적용 범위는 전체 표만 지원한다.
MVP에서는 셀별 스타일을 제공하지 않는다.

기본 UI:
- 배경: `밝게 / 어둡게 / 투명`
- 글자 크기 slider
- 정렬: `왼쪽 / 가운데 / 오른쪽`
- 테두리 ON/OFF

기본값:
- 정렬 = 가운데
- 테두리 = ON

배경 대비:
- 밝게 → 어두운 글자
- 어둡게 → 흰 글자
- 투명 → 기본 흰 글자

투명 선택 시:
- 투명도 slider를 contextually 노출

적용 방식:
- 모든 변경은 실시간 반영
- `적용` 버튼 없음
- Sheet를 닫아도 현재 스타일 유지
- 스타일 진입 시 셀 선택 상태 해제

MVP 제외:
- 직접 글자색 설정
- 테두리 두께 설정
- 빈 `더보기` 메뉴

즉 MVP에서 고급 항목이 없다면 `더보기` 자체를 노출하지 않는다.

## 7. Undo / Redo

Undo/Redo 대상:
- 셀 값 변경
- 셀 타입 변경
- 행/열 추가
- 행/열 삭제
- 병합/병합 해제
- 행/열 크기 조절
- 스타일 변경

단위:
- 셀 편집은 편집 세션 기준으로 자연스러운 단위 유지
- 크기 조절 드래그 1회 전체 = Undo 1단계
- 행/열 추가·삭제 각각 = Undo 1단계
- 병합/병합 해제 각각 = Undo 1단계

## 8. 저장 및 뒤로가기

### 8.1 저장 원칙

- 편집 중 변경은 화면 상태에 즉시 반영
- 영구 저장은 상단 `저장` 버튼으로 확정
- 저장 대상은 현재 표 템플릿
- 저장 성공 후 편집 화면 유지
- 저장 성공 피드백은 `저장되었습니다` 수준의 짧은 Snackbar
- 별도 성공 팝업 없음
- 미저장 상태는 저장 버튼 활성/강조로 표현
- 별도 `●` 표시는 사용하지 않음

저장된 템플릿은 다음 진입 시:
- 표 구조
- 셀 값/타입
- 스타일
- 관련 설정
을 마지막 저장 상태 그대로 복원한다.

### 8.2 뒤로가기

메인 편집 화면에서:
- 변경 없음 → 바로 나가기
- 미저장 변경 있음 → 저장 확인창

확인창 액션:
- `저장 안 함`
- `취소`
- `저장`

동작:
- 저장 → 템플릿 저장 후 나가기
- 저장 안 함 → 마지막 저장 상태를 유지하고 현재 변경 폐기 후 나가기
- 취소 → 편집 계속

새 템플릿이 아직 한 번도 저장되지 않은 경우:
- 동일 확인창 사용
- `저장 안 함` 선택 시 새 템플릿 자체를 생성하지 않음

## 9. 템플릿 관리

### 9.1 기본 동작

- 템플릿 이름 수정 가능
- 기존 템플릿 편집 후 저장 = 해당 템플릿 덮어쓰기
- 새 템플릿은 별도 생성
- 기존 템플릿 기반 `복제` 지원

복제:
- 기본 이름 `기존이름 사본`
- 이후 즉시 이름 수정 가능

새 템플릿:
- 기본 이름 `새 템플릿`
- 중복 시 `새 템플릿 2`, `새 템플릿 3` 식으로 자동 증가
- 기본 시작표 제공
- 현재 V2 기본안은 3×2

### 9.2 템플릿 목록

정렬:
- 최근 수정순 고정
- 즐겨찾기 MVP 제외
- 검색 MVP 제외

카드 정보:
- 템플릿명
- 행×열
- 최근 수정일

불필요한 세부 설정 요약은 카드에 넣지 않는다.

탭:
- 카드 전체 탭 → 바로 편집 진입
- 별도 상세 화면 없음

`⋮` 메뉴:
- 이름 변경
- 복제
- 삭제

삭제:
- 템플릿 목록에서만 제공
- 삭제 확인창 1회

새 템플릿:
- 목록 우측 하단 `+`
- 누르면 기본표로 바로 편집 진입

빈 상태:
- 템플릿이 하나도 없으면 빈 상태 화면 + `새 템플릿 만들기`

편집 화면:
- 템플릿명은 제목 아래 표시
- 이름 변경/복제/삭제 같은 관리 기능은 목록 쪽에 둬 편집 화면을 단순하게 유지

## 10. 저장 규칙 UI 경계

메인 화면에는 `저장 규칙` 진입점만 둔다.

이 문서에서 확정하지 않는 것:
- 파일명 생성 상세 규칙
- 저장 경로 상세 규칙
- 3단계 경로의 실제 저장 정책
- 자동번호 저장 스코프
- 직접입력 타입 상세
- 카운터 동기화/초기화 정책

위 항목은 별도 저장 규칙 논의에서 확정한다.

## 11. 카메라 Preview 책임

레이아웃 화면에서는 표 전체의 화면 위치와 전체 크기를 결정하지 않는다.

이유:
- 실제 카메라 화면 비율과 촬영 영역을 함께 봐야 정확한 배치가 가능함

따라서:
- 표 내부 행/열 구조 → 레이아웃
- 실제 화면 내 표 위치/전체 크기 → 카메라 Preview
