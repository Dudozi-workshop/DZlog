# DZlog 아이폰 정합성 점검표

> 최신 전수 점검 기준은 `docs/ios-final-parity-audit-20261126.md`이다. 이 문서의 초기 결항 목록은 이후 구현으로 대부분 해소되었으며, 과거 CI 기록 용도로만 유지한다.

2026-11-20 기준. 안드로이드 비교 기준은 `integration/dzlog-20261010`의 `4e4fecb7`이다. 다음 목표를 시작할 때 통합 브랜치의 변경도 확인한다. iOS 변경은 PR #87에 모은다.

## 점검 순서

| 순서 | 사용자 흐름 | 두 운영체제에서 대조할 결과 |
| --- | --- | --- |
| 1 | 카메라 초점·밝기·촬영 | 잠금 전후 탭, 밝기를 누른 상태, 화면 가장자리의 링·잠금·슬라이더, 촬영 뒤 밝기와 잠금 유지 |
| 2 | 첫 실행·권한·홈·프로젝트 | 첫 촬영 진입, 카메라·사진 접근 거부 및 설정 복귀, 프로젝트 생성·전환, 앱 재실행 후 선택 복원 |
| 3 | 템플릿·표·빠른 수정 | 템플릿 전환, 셀 병합과 순환 이동, 문구 세트·즐겨찾기, 적용·취소 결과가 촬영 표에 반영되는지 확인 |
| 4 | 촬영·저장·번호 | 화면의 표와 저장 사진 대조, 원본·표 사진·둘 다 저장, 파일명과 번호 증가, 저장 중단·재시도·실행 취소 |
| 5 | 앨범·프로젝트 결과 | 방금 찍은 사진 찾기, 원본과 결과물 전환, 폴더 이동·다중 선택·공유 후 목록과 개수 대조 |
| 6 | 공통 설정·화면·설치본 | Free 상태의 전체 기능 진입, 설정 기본값·재실행, 튜토리얼, 작은 화면·다크 모드, 설치본에서 주요 경로 반복 |

각 목표에서 같은 시작 데이터와 조작을 사용한다. 화면 배치·문구·조작 순서와 저장 결과를 함께 기록한다. 권한은 iOS 시스템에서 실제로 선택할 수 있는 상태별로 촬영·저장 가능 여부와 복귀 경로를 확인한다. 테스트는 변경을 모아서 실행하고 실제 센서·노출·진동은 실기기 확인 대상으로 남긴다.

## 목표 1 진행 기록

- 안드로이드의 초점 결과 표시 시간은 1.2초다. iOS는 초점 조작 후 2.8초를 사용했고 밝기 슬라이더를 누른 채 멈춰도 시간이 흘렀다. 이번 변경에서 초점 요청 처리 후 표시 시간을 1.2초로 맞추고 밝기 터치 종료·취소 시점부터 다시 센다.
- 직전 iOS 커밋 `c3b1dad6`의 아이폰 빌드와 공용 코어 검사를 통과했다. 시뮬레이터 UI 검사 30건 중 28건 통과. 잠금 중 두 번 탭과 밝기 유지도 이 실행에서 통과했다.
- 두 실패 지점은 설정 복귀 테스트의 텍스트 셀 선택과 프로젝트 이름 입력 요소 탐색이었다. 이번 변경에 셀 직접 선택, 프로젝트 이름 접근성 레이블, 시스템 키보드 입력, 초점 자동 축소 검사 한 건을 포함했다. 새 결과는 다음 묶음에서 기록한다.
- 다음 대조 지점은 초점 링 위·아래에 배치되는 잠금과 밝기 슬라이더다. 현재 iOS는 잠금을 옆에 두고 밝기 슬라이더를 위에 먼저 배치한다. 화면 끝에서의 터치 영역, 자동초점 성공·실패 표시 및 실제 촬영 후 잠금 유지까지 확인하면 이 목표를 마칠 수 있다.

### 초점 링 배치와 터치 영역

- `d075321c`에서 아이폰 기기 빌드와 공용 코어 검사가 통과했다. 시뮬레이터는 31건 중 29건 통과했다. 빠른 수정 셀 선택, 잠금 중 재초점, 시뮬레이터 PhotoKit 저장 후 잠금·밝기 유지는 통과했다.
- 이번 변경은 안드로이드 통합본의 배치 계산과 경계 조건 테스트 6건을 공용 코어에 옮겨 아이폰 미리보기에 적용한다. 링 반지름은 펼친 상태 22pt, 접힌 상태 20pt다. 기본 잠금 위치는 위, 밝기 위치는 아래다. 사진 위쪽과 아래쪽에서는 조작 영역이 사진 안에 들어오도록 위치를 바꾼다.
- 잠금 터치 영역은 48pt, 밝기 영역은 108×48pt다. 잠근 뒤 링 중앙 36pt를 누르면 밝기 조절이 열린다. 여백을 제외한 실제 사진을 기준으로 조작부를 놓고 탭을 카메라 좌표로 변환한다.
- 이전 실행에서 자동 축소 검사의 첫 상태 조회가 1.2초를 넘겼다. 이제 자동 축소 검사는 탭 적용 및 최종 링 지름을 확인하고, 가장자리 검사는 별도로 펼친 링과 잠금 버튼·슬라이더의 실제 프레임을 확인한다. 프로젝트 생성 검사도 프로젝트 이름이 포함된 목록 행과 홈 버튼을 직접 확인한다.
- 남은 카메라 확인 항목은 센서 초점 완료·실패 표시와 아이폰 실물에서 촬영 후 실제 노출·초점 유지다.

### 터치 자동초점의 결과 표시

- 직전 배치 `80c16ff3`의 아이폰 기기 빌드·공용 코어·안드로이드 통합 검사가 통과했다. 확인 시점에 시뮬레이터 UI 검사는 진행 중이었다.
- 탭하면 초점 링이 맥동한다. 아이폰은 일회성 자동초점 요청 뒤 렌즈가 잠기거나 실제로 관찰된 초점 조정이 끝났을 때 완료로 표시한다. 사진의 선명도는 실기기에서 확인한다.
- 요청이 거절되면 0.5초 동안 빨간 링을 표시한다. 완료·거절 결과는 1.2초간 유지하고, 밝기 슬라이더를 누르고 있는 동안에는 접지 않는다. 2초간 응답이 없으면 맥동을 끝내며 잠근 링은 유지한다.
- 새 초점 요청, 촬영으로 인한 입력 중지, 화면 종료가 이전 요청의 피드백을 취소한다. 실패·무응답·다음 탭 복구를 같은 시뮬레이터 검사로 묶었다.
- 실물 아이폰에서 가까운 대상과 먼 대상을 연속으로 눌러 렌즈 반응과 링 표시를 대조하고, 밝기를 잠근 뒤 연속 촬영한 사진도 비교해야 한다. 다음 소프트웨어 대조 목표는 첫 실행·권한·홈·프로젝트다.

## 목표 2 진행 기록

### 첫 실행과 설정 복귀

- 안드로이드 통합본의 카메라 → 사진 순서와 설정 복귀 시 실제 권한 재확인을 기준으로 삼았다. 아이폰은 PhotoKit 사진 보관함을 사용하며 전체 허용과 선택한 사진 접근을 구분한다.
- 촬영 화면은 카메라 사용과 사진 저장에 필요한 접근이 모두 준비됐을 때 미리보기를 시작한다. 권한이 바뀌면 미리보기와 자동번호 준비 상태를 다시 확인한다. 거부된 카메라가 있어도 사진 접근을 허용하면 앨범은 열 수 있다.
- 사진 권한이 바뀌거나 선택한 사진 목록이 달라질 수 있는 시점에 홈 최근 사진·촬영 썸네일·프로젝트 결과를 다시 조회한다. 복구 대기 중인 촬영이 있으면 홈에서 필요한 사진 접근을 요청하거나 선택한 사진을 변경할 수 있다.
- 직전 초점 패치 `d16285aa`는 아이폰 빌드와 시뮬레이터 UI 검사 33건을 모두 통과했다. 이번 묶음에는 사진 거부 → iPhone 설정에서 전체 접근 허용 → 갤러리 복귀 후 카메라 거부 유지 경로를 추가했다.
- 다음은 첫 촬영 설정을 거쳐 일반 촬영과 프로젝트 촬영을 전환하고 재실행했을 때 프로젝트·템플릿·저장 위치가 함께 복원되는지 확인한다.

### 일반 촬영과 프로젝트 사이의 템플릿 전환

- 홈과 카메라는 프로젝트를 떠날 때 현재 템플릿을 기억한다. 돌아오면 그 프로젝트에서 마지막으로 쓴 템플릿을 선택한다. 기억한 템플릿을 삭제했으면 현재 템플릿, 목록의 첫 템플릿 순으로 찾는다.
- 빠른 수정에서 템플릿을 바꿀 때 입력 중인 값과 선택을 함께 저장한다. 각 템플릿의 저장 경로와 다음 번호를 그대로 읽으며, 두 프로젝트가 같은 템플릿을 쓰면 그 템플릿의 번호를 공유한다. 현재 프로젝트를 완료하거나 삭제하면 일반 촬영의 템플릿을 복원한다.
- 회귀 검사에 서로 다른 두 경로와 번호, 앱 재실행 및 왕복 전환, 사라진 템플릿 대체, 같은 템플릿의 번호 공유를 추가했다. 로컬에서 iOS 배포 메타데이터와 UI 번호 접근 규칙 검사를 통과했다. 새 시뮬레이터 검사와 공용 테스트의 실행 결과는 다음 묶음에서 확인한다.
- 다음 대조 대상은 표 상세와 빠른 수정의 셀 이동, 문구 세트·즐겨찾기, 적용·취소 후 촬영 표에 보이는 값이다.

## 목표 3 진행 기록

- 안드로이드 통합본 `4e4fecb7`과 대조했다. 표 상세와 빠른 수정 모두 병합된 셀을 한 번만 방문하고 첫 셀과 마지막 셀을 양방향으로 연결한다. 텍스트 즐겨찾기는 한 줄로 표시하고 긴 문구를 눌렀을 때 전체 문구를 적용한다.
- 빠른 수정에서 키보드가 열린 채 다른 텍스트·숫자 셀로 이동하면 새 셀의 끝에서 입력을 이어 간다. 자동 입력 셀로 가면 키보드를 닫는다. 텍스트 입력창 확대·축소도 지원한다. 즐겨찾기 적용 뒤에도 커서는 문구 끝에 놓인다.
- 시뮬레이터 검사에 키보드로 셀을 연속 편집한 뒤 파일명 미리보기를 확인하고, 순환문구 세트를 바꿨다가 취소하면 이전 값이 남는 경로를 추가했다.
- 직전 커밋 `2f2d8baf`의 기기 빌드·공용 코어·통합 검사는 통과했다. 시뮬레이터 34건 중 31건 통과. 첫 실행 때 저장 후 다시 읽은 템플릿과 화면에 남은 템플릿이 달라질 수 있어 프로젝트 변경이 거절되는 경로를 수정했다. 시스템 설정이 앱 목록에서 열리는 경우를 검사에 추가했고 사진 저장 검사는 권한 상태를 초기화하고 시작한다.
- 다음 대조 대상은 순환문구의 주기·진행 횟수 충돌 조정과 표 상세에서 적용한 값의 촬영 미리보기 반영이다.

### 표 상세의 순환문구와 촬영 미리보기

- 안드로이드 기준 `4e4fecb7`의 세트 기본 주기, 개별·다중 선택 주기, 문구 검색과 목록 편집을 아이폰 표 상세에 반영했다. 검색 결과에서 선택해도 원래 목록의 해당 행을 편집한다.
- 목록 끝에 문구를 추가하면 이미 진행 중인 문구와 완료 장수를 유지한다. 주기를 바꿔도 범위 안인 셀은 그대로 두고, 새 주기 이상을 이미 촬영한 셀만 조정한다. 취소하면 변경 전 상태가 유지된다.
- 회귀 테스트는 12장 주기로 5장을 찍은 셀을 3장 주기로 줄이고, 다음 문구 T4의 2장 완료 상태를 선택해 저장하는 예를 사용한다. 편집 미리보기·촬영 표·파일명이 T4인지, 성공 처리 뒤 다음 표가 T1의 0장인지 확인한다.
- 직전 `249c94f3`은 조회 시 아이폰 기기 빌드·공용 코어·통합 CI를 통과했다. 시뮬레이터 검사는 진행 중이었다. 아이폰의 순환문구 CSV 파일 가져오기·내보내기는 남은 항목이다.

### 파일명·폴더 미리보기 후속 (로컬 검토, 실행 결과 대기)

- 빠른 수정의 파일명·폴더 안내에 안드로이드와 같은 선택 셀 강조를 적용한다. 문자열을 검색해 칠하지 않고 공용 슬롯 출처 계산을 사용하므로, 직접 입력한 문구와 선택 셀 값이 같아도 해당 셀이 만든 부분만 강조한다.
- 원본·표 사진 동시 저장에서는 두 폴더 줄에 각각 같은 셀의 기여 부분을 강조한다. 원본 전용 경로의 original/ 접미사는 선택한 텍스트로 잘못 강조하지 않는다.
- 저장 미리보기 결과를 기준으로 유지하며, 강조용 계산과 결과가 달라지면 강조만 생략한다. 파일명·번호·촬영 저장 동작은 바꾸지 않는다.
- 공용 테스트 4건을 추가했다. 동일한 문자열의 위치 구분, 세 저장 방식, 잘못된 강조 범위, 루트와 이미 원본인 경로를 확인한다. 로컬 Gradle 실행은 배포본 다운로드의 Network is unreachable 오류로 막혔고, 권한을 높여 재시도해도 같았다. Kotlin 테스트·iOS 컴파일·시뮬레이터 시각 검증은 아직 통과로 기록하지 않는다.

### 순환문구 CSV

- 표 상세의 세트 편집 → CSV 일괄 관리에서 파일 앱을 열어 CSV를 읽거나 저장한다. 안드로이드 통합본과 같은 UTF-8 3열 형식이다. 순서·문구·개별 주기를 옮기며 주기를 비우면 대상 세트의 기본 주기를 사용한다.
- 가져오기 전에 기존·새 문구 수와 첫 세 문구·주기를 표시한다. 목록 교체 후 표 편집에서 저장해야 확정된다. 형식 오류와 취소는 기존 목록을 보존한다.
- 안드로이드 CSV 호환 테스트를 공용 테스트로 옮겼고, 아이폰 검사에 실제 파일 선택기에서 가져오기·내보내기를 취소한 뒤 원래 목록을 확인하는 경로를 추가했다. 직전 순환문구 테스트의 Android 로컬 단위 테스트가 JSON 초기화에서 실패해 Robolectric 환경에서 실행하도록 수정했다.
