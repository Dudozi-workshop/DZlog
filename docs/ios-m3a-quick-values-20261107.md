## 이번 구현

- 카메라의 빠른 입력 화면에서 편집 가능한 텍스트·숫자 셀을 행/열 순서로 입력한다. 저장된 병합 레이아웃을 먼저 검증하고, 가려진 셀·고정 제목·날짜/시간·번호/순환문구는 수동 입력 대상에서 제외한다.
- Android와 같은 signed decimal 입력 유틸을 사용한다. 소수·부호·후행 0을 보존하며 타입·서식·병합·저장 규칙·번호·배치를 바꾸지 않는다.
- 입력 중 파일명·논리 저장경로 미리보기를 갱신하고 관련 셀 안내를 표시한다. 완료 시 같은 iOS 문서에 저장해 카메라 표/파일명과 다음 촬영에 반영한다. 취소는 저장하지 않는다.
- 입력 화면 동안 카메라 세션·표 시계 갱신을 중지하고 복귀 시 재시작한다. 촬영/표 조작/복구 대기에는 진입을 차단한다. 완료 시 열린 당시 문서 및 디스크 워크스페이스를 확인해 다른 변경을 덮어쓰지 않는다.
- 기존 iOS의 문서별 확정 번호는 보존한다. 파일명/경로별 Photos max+1 자동 재동기화 기능은 이번에 추가하지 않는다.
- Android 제품 코드·공통 제품 코드·사용자 데이터는 변경하지 않는다.

## 검증 요청

새 센서 fixture의 입력만 합성 JPEG이며 production 입력 화면·저장 문서·렌더러·PhotoKit을 사용한다.

1. 실제 키보드로 텍스트 입력 → 취소 시 원래 값 → 다시 입력/완료 → 파일명 반영 → PhotoKit 저장 → 번호 12→13 → 재실행 후 텍스트/숫자/번호 유지.
2. 병합에 가려진 셀·고정 셀·자동 셀·알 수 없는 ID 거부, 부호/소수/후행 0 보존, 비정상 숫자·잘못된 병합 거부, 외부 세션이 바꾼 워크스페이스 덮어쓰기 차단, 렌더러 연결.
3. 실제 네이티브 카메라 모달에서 빠른 입력 진입/취소·촬영 설정 변경/복귀, 권한 거부 상태의 촬영 비활성화 유지.

`[ios-quick-values]` 커밋은 위 관련 UI 3개만 우선 실행한다. media 묶음에는 새 2개를 포함해 21개, 전체 UI는 29개다. 전체 검증 마커/리뷰 단계가 부분 실행보다 우선한다. 부분 성공은 전체 29개 통과로 계산하지 않는다.

로컬 공백·shell 문법 검사, workflow YAML 파싱, 모든 선택 테스트 이름 존재 및 전체 29개 개수 검사, CI scope 선택(부분/전체 우선순위/리뷰/일반/수동) 검사를 통과했다. Apple SDK가 없어 Kotlin/Native 컴파일·실제 XCTest는 새 macOS CI 결과가 필요하다. CI를 대기하지 않는다.
