# Build/Gradle 실행 환경 가이드

이 문서는 **저장소 설정**과 **실행 환경 표준화**를 분리해서 정리합니다.

## 1) 현재 저장소 설정(확정)

- 저장소에는 `org.gradle.java.home=/...` 같은 **개발자 머신 절대경로를 넣지 않습니다**.
- Android app 모듈은 JDK 21 toolchain을 사용하도록 설정되어 있습니다.
  - Kotlin: `jvmToolchain(21)`
  - Java/KSP: `languageVersion = 21`
- 산출 바이트코드 target은 JVM 17을 유지합니다.
  - Kotlin `jvmTarget = JVM_17`
  - (의미) 빌드 도구 실행은 JDK 21 기준으로 맞추고, 앱 실행 호환성은 JVM 17 기준을 유지합니다.

## 2) 왜 “절대경로 제거”만으로 완결이 아닌가

절대경로를 제거하면 저장소 이식성은 좋아집니다.  
하지만 개발자가 로컬에서 JDK 25를 기본으로 Gradle을 실행하면, Gradle 초기화 단계에서 실패할 수 있습니다.

즉, 남은 이슈의 본질은:

- 저장소 설정 문제 ❌ (이미 개선됨)
- 실행 환경 표준화 미완료 ✅ (CI/개발 가이드로 해결 필요)

## 3) 권장 운영 표준

### CI
- Gradle 실행 JDK를 **21로 고정**합니다.
- 빌드/테스트/lint 잡은 동일 JDK 기준으로 돌립니다.

### 로컬 개발(IDE/CLI)
- Android Studio Gradle JDK를 21로 설정합니다.
- CLI 실행 시 `JAVA_HOME`이 JDK 21을 가리키도록 맞춥니다.

### 로컬 선택 힌트
- 저장소 루트의 `.mise.toml`은 optional 힌트입니다.
- mise/asdf 계열 사용자에게는 JDK 21 선택에 도움을 주지만, 강제 수단은 아닙니다.

## 4) 네트워크 제한 환경 주의

프록시/네트워크 제약이 있는 환경에서는 plugin resolution 단계에서 403 등으로 막혀  
test/lint 완주 검증이 제한될 수 있습니다.

이 경우:
- “JDK 파싱 이슈 해소 여부”와
- “네트워크로 인한 외부 플러그인 해석 실패”

를 분리해서 판단해야 합니다.

## 5) 팀 가이드에 넣을 권장 문구(복붙용)

- “빌드는 JDK 21로 수행하고, 앱 바이트코드는 JVM 17 호환성을 유지한다.”
- “로컬 절대경로를 저장소에 고정하지 않고, CI 및 개발 가이드에서 JDK 21 사용을 표준으로 삼는다.”
- “기본 JDK 25 환경에서는 Gradle 초기화 실패가 발생할 수 있으므로, Gradle 실행 JDK는 21로 맞춘다.”
