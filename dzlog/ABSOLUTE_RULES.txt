DZlog 절대규칙 (변경 시 기준)

1) 작업 절차
- 변경은 1회에 1개 이슈 단위로 쪼개서 진행한다.
- 각 단계는 컴파일/실행이 가능한 상태를 유지한다.
- 패치는 항상 (1) 변경요약, (2) git diff(클립보드용), (3) 에뮬 체크리스트 3종 세트로 제공한다.
- 추론으로 결정하지 않는다. 애매하면 질문하고, 결정 후 반영한다.

2) 카운터 정책
- 카운터 스트림 키 = relativePath + counterPrefix
- counterPrefix는 "파일명 포함 셀" 기반 prefix이며, 날짜/시간은 스트림에 포함하지 않는다.
- next counter = 해당 스트림에서 사용된 최대값 + 1

3) 저장경로(구성요소) 정책 — 2026-10-27
- 셀 기반 G1/G2 상하위 폴더 지정 정책은 폐기했다. 관련 UI, 메타데이터, 두 단계 앨범 구조를 새 코드에 도입하지 않는다.
- 저장경로의 단일 근거는 각 템플릿의 pathSlotDrafts이다(최대 5개). 구성요소를 설정한 순서대로 해석하고 빈 값은 제외한다.
- 저장경로 구성요소가 없으면 Pictures/DZlog/ 에 저장한다. 값이 있으면 Pictures/DZlog/<구성요소1>/<구성요소2>/.../ 형식으로 이어 붙인다.
- 최종 결과사진은 기본 상대경로, 원본사진은 해당 경로의 original/ 하위 폴더에 저장한다. 단, 실제 저장 여부는 촬영 저장 모드에 따른다.
- 갤러리는 실제 저장된 폴더 경로를 탐색하며, G1/G2처럼 깊이를 두 단계로 제한하지 않는다.
- 저장 규칙 변경은 과거 사진 파일을 자동 이동·삭제하는 근거가 되지 않는다.

※ 위 규칙은 이름/경로 구성요소와 실제 사진 폴더의 관계만 규정한다. 자동번호 스코프 상세 규칙은 관련 도메인 정책을 따른다.
